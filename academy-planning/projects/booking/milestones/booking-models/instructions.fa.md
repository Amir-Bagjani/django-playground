# مرحله‌ی ۳ — پیاده‌سازی Django Models

حالا همان مدل را با **Django ORM** بنویس. کد تو با `makemigrations` و `migrate` روی یک دیتابیس MySQL واقعی اجرا می‌شود و جدول‌ها ساخته می‌شوند.

## خواسته‌ها

دو Model در فایل تعریف کن:

1. `Room` — شماره/نام اتاق و ظرفیت. Django خودش کلید اصلی خودکار می‌سازد (لازم نیست صریح تعریف کنی).
2. `Booking` — نام مهمان، تاریخ ورود، تاریخ خروج و یک `ForeignKey` به `Room`.

## نکته‌های فنی

- برای رابطه از `models.ForeignKey(Room, on_delete=..., related_name=...)` استفاده کن.
- `on_delete` را از روی معنای کسب‌وکار انتخاب کن (مثلاً وقتی اتاق حذف می‌شود، رزروهای آن چه شوند؟).
- برای تاریخ‌ها `DateField` و برای ظرفیت `PositiveIntegerField` مناسب است.
- برای فیلدهای اجباری `null=False` (پیش‌فرض) بگذار؛ برای ستون کلید خارجی نباید NULL مجاز باشد.
- نام‌ها را طوری بگذار که با مرحله‌ی SQL هم‌خوان باشند (اتاق و رزرو).

## یادداشت مهندسی (بازبینی دستی)

در یک کامنت کوتاه توضیح بده چرا این نوع فیلدها و این `on_delete` را انتخاب کردی. این بخش دستی بررسی می‌شود و در قبولی خودکار اثری ندارد.

**قبولی خودکار:** کد با Migration روی MySQL واقعی اجرا می‌شود، سپس ساختار جدول‌های ساخته‌شده (کلید اصلی، کلید خارجی، NOT NULL) و اعمال Migration بررسی می‌شوند — نه متن کد.
